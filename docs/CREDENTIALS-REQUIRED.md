# OmniRank Alpha Credentials — Free-First and Phase-Gated

Do not collect paid infrastructure credentials up front.

OmniRank Alpha uses the concrete free-first stack in `docs/FREE-ALPHA-STACK.md`.
Credentials are required only immediately before the phase that needs them.

## Secret-handling rules

- Never commit secrets to Git.
- Never print, echo, log, snapshot, or place secret values in prompts.
- Configure secrets only in local/server environment variables or approved secret stores.
- Use test/sandbox credentials for development.
- Record only PASS/FAIL and non-secret identifiers.

## Phase P07 / current requirement

### Supabase
Already the Alpha backend for database/auth/RLS/pgvector/storage.

Required:
- project URL / publishable client key
- trusted server key or authenticated server access
- migration/deployment access to the existing OmniRank project

Live verification:
- inspect schema
- safe read/write fixture
- deploy migration when approved
- RLS/RPC test
- Supabase Storage private-object test when storage is used

No Cloudflare/R2 credential is required for Alpha.

## Before OR-P08

### OpenRouter only

Required:
- OPENROUTER_API_KEY
- OPENROUTER_ALPHA_BUDGET_USD

Live verification:
- one structured-output call through an OpenRouter free model/route where suitable
- one controlled fallback to another model/provider available through OpenRouter
- one low-cost paid smoke test only if necessary and inside the configured budget
- verify ai_usage_events captures model/provider/tokens/latency/cost

No direct OpenAI, Anthropic, Gemini or Cloudflare AI Gateway credential is required for Alpha.

## OR-P10 WordPress

No external credential is required up front.

Use a local WordPress instance started with `@wp-playground/cli`.

OR-P10 must create/configure its dedicated local integration user/application-password path and exercise the real WordPress REST API locally.

A hosted WordPress account, WPVibe and paid staging site are not Alpha prerequisites.

### Google Search Console + GA4

Required:
- GOOGLE_CLIENT_ID
- GOOGLE_CLIENT_SECRET
- GSC_SITE_URL
- GA4_PROPERTY_ID

Live verification:
- authorize the user's Google account
- read configured Search Console property
- read configured GA4 property
- persist at least one real small sync window

## OR-P12 automation

No Inngest account is required for Alpha.

The concrete Alpha automation runtime is:
- Supabase Queues / pgmq
- Supabase Cron / pg_cron
- local worker or Supabase Edge Function as appropriate
- workflow_runs/workflow_steps for app-level state/audit

## Alpha email

No Resend account is required for the original Alpha success loop.

Use:
- Supabase Auth email path for authentication testing
- in-app notification records/UI for automation notifications

Transactional email provider integration is a Beta/production-hardening concern unless the product requirements are explicitly changed.

## Not required for Alpha

- Cloudflare
- R2
- Cloudflare AI Gateway
- Inngest
- WPVibe
- Resend

## Completion rule

Free-first is not permission to mark incomplete features complete.

Each phase must exercise the real concrete Alpha implementation end-to-end.

A future paid adapter may be deferred only when the same capability already works in Alpha behind the provider-neutral interface.
